# Work 3 — Streamlit-приложение с LLM-аналитикой

## Что это

Мини-продукт для анализа CSV-датасетов через веб-интерфейс Streamlit. Пользователь загружает CSV-файл, пишет инструкцию или контекст анализа, а приложение отправляет файл LLM-агенту. Агент сам запускает Python-код в Code Interpreter, считает метрики, ищет закономерности и возвращает аналитический отчёт на русском языке.

Важно: приложение не подставляет заранее посчитанные метрики в промпт. CSV передаётся в code-interpreter контейнер, и LLM должна сама прочитать файл, выполнить анализ кодом и при необходимости построить графики.

## Возможности

- загрузка CSV-файла через Streamlit;
- пользовательская инструкция к анализу;
- агентный анализ через Responses API + `code_interpreter`;
- отчёт на русском языке с метриками, качеством данных, инсайтами и рекомендациями;
- скачивание JSON-ответа API;
- отображение и скачивание файлов, которые сгенерировал Code Interpreter;
- защита от prompt-injection в пользовательской инструкции и системном промпте.

## Настройка

Создайте виртуальное окружение и установите зависимости:

```bash
cd work-3
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Скопируйте шаблон env-файла:

```bash
cp .env_example .env
```

Заполните `.env`:

```env
LLM_API_KEY=ваш_api_ключ
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4.1
LLM_PROVIDER_NAME=openai
CODE_INTERPRETER_MEMORY=1g
MAX_UPLOAD_MB=20
```

Файл `.env` содержит секреты и игнорируется git.

## Универсальность настройки

Настройки сделаны в том же стиле, что и во второй работе: ключ, base URL и модель задаются через `.env`. Однако для выполнения требований задания провайдер должен поддерживать Responses API и tool `code_interpreter`.

То есть приложение рассчитано на OpenAI Responses-compatible API. С ключом OpenAI формата `sk-proj...` это основной сценарий. Если у другого провайдера есть совместимый endpoint для Responses API и Code Interpreter, можно поменять `LLM_BASE_URL`, `LLM_MODEL` и ключ. Если у провайдера только Chat Completions без code-interpreter tool, требование задания не будет выполнено без отдельного адаптера или MCP-сервера.

## Запуск

Из папки `work-3`:

```bash
streamlit run app.py
```

После запуска откройте локальный адрес, который покажет Streamlit, обычно:

```text
http://localhost:8501
```

## Как пользоваться

1. Загрузите CSV-файл.
2. Введите инструкцию, например: “Найди ключевые драйверы выручки, проверь выбросы и предложи бизнес-выводы”.
3. Нажмите “Запустить LLM-анализ”.
4. Дождитесь отчёта.
5. При необходимости скачайте JSON-ответ API или файлы, созданные Code Interpreter.

## Prompt-injection защита

Защита реализована на двух уровнях:

- пользовательская инструкция проверяется на явные попытки переопределить системные правила, раскрыть ключи или игнорировать инструкции;
- системный промпт явно сообщает агенту, что CSV, имена колонок, значения ячеек, имя файла и пользовательский текст являются недоверенными данными.

Если в пользовательской инструкции обнаружена подозрительная попытка prompt-injection, приложение не отправляет запрос к LLM и просит переписать инструкцию.

## Что должно быть в результате

Отчёт должен содержать:

- краткое описание датасета;
- размер данных и типы колонок;
- пропуски и возможные проблемы качества данных;
- ключевые метрики;
- тренды и взаимосвязи;
- аномалии или выбросы;
- бизнес-инсайты;
- ограничения анализа;
- следующие шаги.

Финальный отчёт не должен состоять из Python-кода или обещания “сейчас посчитаю”. Код выполняется внутри Code Interpreter, а пользователю показываются уже посчитанные значения, выводы и интерпретация. Технический список вызовов Code Interpreter отображается отдельно в диагностическом блоке.
